# Preparing for Technical Interviews

> Practise problem solving out loud, review fundamentals, and know your own projects deeply.

## Common formats
- **Online assessment**: timed coding problems (HackerRank, Codility) or multiple-choice questions.
- **Live coding**: solve a problem while talking through your thinking.
- **Take-home task**: build a small feature or API in a few days.
- **Technical discussion**: questions about your projects, databases, networking, or the stack in the job description.

## How to prepare
1. **Fundamentals**: arrays, strings, hash maps, stacks/queues, trees, sorting, recursion and Big-O. Learn patterns (two pointers, sliding window, BFS/DFS) rather than memorising answers.
2. **Practise regularly**: 30–45 minutes a day beats a weekend cram. Start with easy problems and explain each solution aloud.
3. **Your stack**: if the role mentions SQL, be ready to write joins and GROUP BY; for web roles, explain HTTP, REST and how a request reaches a server.
4. **Your projects**: be able to explain every design choice, what broke and what you'd improve.

## During the interview
- Repeat the problem in your own words and ask clarifying questions.
- Start with a simple working solution, then improve it.
- Think aloud: interviewers grade your reasoning, not just the final code.
- Test with a small example and edge cases (empty input, duplicates, very large values).
- If you're stuck, say what you're considering. Hints are normal.

## For take-home tasks
Write a short README: how to run it, decisions you made, and what you would add with more time. Clean commits and a few tests stand out.
